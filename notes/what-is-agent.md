# 面试必答 0 号题：什么是 Agent

> **为什么这道题最危险：** 它看起来是送分题，其实是分水岭题。多数人答"Agent = 有智能的实体"（背课本），高手答"Agent = 把 LLM 放进循环"（讲本质）。**能答对的人很多，能让面试官觉得"这人真的懂"的很少。**
> **适合谁：** 任何要面 Agent 岗位的人。建议面试前 30 分钟默背文末"三句核心记忆卡"。
> **关联文档:** [面试话题总清单](./agent-interview-questions.md)、[从零到一构建 Agent（总纲）](../topics/agent-architecture/from-zero-to-agent.md)

## 📌 名词速查表（先看这里）

| 英文 | 读作/理解成 | 一句话解释 |
|------|------------|-----------|
| **Agent** | "智能体" | 把 LLM 放进 while 循环、让模型自己决定下一步的系统 |
| **LLM** | "大语言模型" | 只能"一问一答"的模型（Agent 的"大脑"） |
| **Loop / 循环** | "循环" | Agent 反复调用模型的机制（Agent 的"骨架"） |
| **Memory** | "记忆" | 补 LLM"没状态"的短板（外设一） |
| **Tool** | "工具" | 补 LLM"没手脚"的短板（外设二） |
| **Reflection** | "反思" | 补 LLM"不纠错"的短板（外设三） |
| **Retrieval** | "检索" | 补 LLM"知识截止"的短板（外设四） |
| **Workflow** | "工作流" | 步骤写死的自动化流程（**不是** Agent） |
| **Agentic** | "智能体化程度" | 决策权让渡给模型的比例 |
| **Skill** | "技能/方法论" | 一套引导 Agent 调多个工具的操作手册（比 Tool 高一层） |
| **MCP** | "模型上下文协议" | 工具/数据标准化接入 Agent 的协议（比 Tool 低一层） |

---

## 🎯 核心回答（60~90 秒，五层递进）

> 面试时按下面五层逐层说，每层都对应面试官心里的一个潜台词。说完第 3 层，面试官基本就给你打"懂"勾了。

### 第 1 层：一句话剥离包装，说本质（破冰）

> "Agent 的核心不是'智能'，而是'**循环**'。它本质上就是一句话：**把 LLM 放进一个 while 循环里，让模型自己在每一轮决定下一步做什么，直到任务完成。** 我们平时调 LLM API 只调一次，Agent 是在反复地调——每一次调用都用上一步的结果和工具返回来更新它的'认知'。"

**为什么加分**：面试官听到"不是智能是循环"这个角度，就知道你想过本质，不是在背"智能体=有智能的实体"这种废话。

### 第 2 层：说透"为什么需要 Agent"——单次调用有四个致命短板

> "为什么要这个循环？因为**一次 LLM 调用是一个'哑巴'**，它同时有四个短板：**没有状态**（不记得上一轮说了什么）、**没有手脚**（不能查数据库、不能执行代码）、**不会纠错**（答错了也不能自己发现）、**知识有截止日期**（训练完就固化了）。Agent 的循环本质上就是给这个哑巴装上外设：**用记忆补状态、用工具补手脚、用反思补纠错、用检索补知识。**"

**为什么加分**：这句话把 AI 对 Agent 的理解和所有案例串起来了——记忆、工具、检索、反思，这四个模块不是凭空设计的，都是为了补 LLM 的四个短板。

### ⚠️ 追问防御：四外设 vs Tool / Skill / MCP（最容易混的点）

> 面试官很爱追问"那 Skill、MCP 算不算外设？"——**这是不同维度的东西，不能对号入座。**

**四个外设 = 按"补什么短板"分类（要干什么）**，而 Tool / Skill / MCP 是"怎么干"的维度：

| 概念 | 属于什么 | 本质 | 类比 |
|------|---------|------|------|
| **四个外设**（记忆/工具/反思/检索） | 功能维度 | 补 LLM 的四个短板 | "缺什么装什么" |
| **Tool（工具）** ✅ = 外设之一 | 就是外设之一 | 单个可调用的函数：`read_file`、`bash` | 一把螺丝刀 |
| **Skill（技能）** | 比 Tool 高一层的封装 | 一套"方法论 + 操作手册"，引导 Agent 调**多个**工具 | 一本《修车指南》 |
| **MCP** | 比 Tool 低一层的接入标准 | 工具/数据**标准化接入** Agent 的协议 | 国标插座（USB-C） |

```
Agent 的四个外设（按"补什么短板"分）
├── 记忆 Memory        ← 没有状态
├── 工具 Tool ⭐       ← 没有手脚
│     └── 工具怎么接进来？→ MCP 🔌（标准协议，像 USB-C）
│     └── 工具怎么组织起来用？→ Skill 📖（方法论手册，调多个工具）
├── 反思 Reflection    ← 不会纠错
└── 检索 Retrieval     ← 知识截止
```

**一句话总结**：
- **Skill = 外设的"使用说明书"**（比 Tool 高一层，调多个工具的完整方法论）
- **MCP = 外设的"插头标准"**（比 Tool 低一层，工具怎么标准化接入的基础设施）

**面试答法**："四个外设是按'补 LLM 短板'的功能分类；Tool 是其中一个（手脚）；Skill 是外设之上的方法论封装（怎么用工具），MCP 是外设之下的接入协议（工具怎么接进来）——它们不在同一个维度上。"

### 第 3 层：点出真正的分界线——"谁在做决策"（全场高光）

> "但我要强调一个关键边界：**有没有 while 循环不代表你是 Agent，'决策权在谁手里'才代表。** 如果每一步调哪个工具、什么时候结束都是**代码写死的**，那叫**工作流（Workflow）**——它确定、可控、可预测，但不是 Agent。真正 Agent 的标志是：**模型自己在决定**'这一步我是该再查一个数据，还是该生成答案了'。**不确定性让位给了模型，这就是 Agent。** 所以业界现在常说的 Agentic（智能体化）程度，本质就是在衡量这个'决策权让渡的比例'。"

**为什么加分**：**这是全场题眼。** 大多数候选人答到第 2 层就停了，你说出"Agent vs Workflow 的分界线是决策权"这一句，面试官会直接在心里标记"这人懂"。因为它表明你**踩过坑**——见过"看似 Agent 实则写死"的伪 Agent。

### 第 4 层：回到工程现实——原理简单，做好极难（体现你真做过）

> "不过把循环跑起来是五分钟的事，**把它做好是另一个量级的事**。真正做 Agent 系统的时候，三个问题才是决定成败的：
> **一是上下文治理**——循环每走一步都在累积消息，窗口很快会被撑爆，所以必须有压缩、剪枝、摘要的成套机制；
> **二是可靠性**——LLM 的输出不可控，工具可能失败，模型可能幻觉，所以必须设计'规则兜底'和'自反思质检'；
> **三是可观测性**——一次回答背后是几十次调用，出问题必须能回放模型每一步的决策过程，否则就是黑盒排障。
> 这三件事，哪一个做得不好，Agent 都只能在 demo 里秀，上不了生产。"

**为什么加分**：第 1~3 层讲的是"知识"，第 4 层讲的是"经验"。面试官最怕招到"只会跑 hello world agent"的人，你主动说出工程化的三个难点，等于告诉他"我踩过这些坑"。

### 第 5 层：落到自己的实践（收尾，证明不是空谈）

> "说到这，我在我们项目里就是按这个理解落地的：核心是一个**统一的执行引擎**，循环逻辑只写一遍，通过'不同的系统提示词 + 不同的工具集 + 不同的轮数上限'构建不同角色；再配上记忆系统补状态、RAG 补知识、自反思补纠错。**我的体会是：Agent 的骨架就是这个循环，血肉是四个外设，而灵魂是'决策权在模型手里'——你把这三句话想清楚了，Agent 对你就不再是黑魔法。**"

## 避坑清单（千万别踩）

| ❌ 别做 | ✅ 要做 |
|--------|--------|
| 只说"Agent = 有智能的实体" | 说"Agent = LLM + 循环 + 四个外设" |
| 堆术语：ReAct、Plan-and-Execute 名词轰炸 | 用"决策权在谁手里"一句话讲清 Agent vs Workflow |
| 只讲原理不讲困难 | 主动讲上下文治理/可靠性/可观测性三个坑 |
| 理论飞到天上 | 结尾落到自己项目，哪怕很小 |
| 背 OpenAI 文档定义 | 用"哑巴装外设"这种自己的类比重建理解 |

## 追问防御（面试官大概率这样追问）

| 追问 | 怎么接 |
|------|--------|
| "那你觉得 Agent 和传统自动化脚本什么区别？" | 就是第 3 层：脚本是"决策写死"，Agent 是"决策交给模型" |
| "ReAct 是什么？" | "就是一种最简单的循环范式：Reason（思考）→ Action（行动）→ Observation（观察结果），把观察喂回下一步思考。我们项目的执行引擎就是这个循环的实现。"（可引`case-study-bondseek-multi-agent.md`） |
| "你这个 Agent 怎么防它跑偏/失控？" | 第 4 层可靠性：三个机制——**轮数上限**（防死循环）、**工具失败降级**（3 连败强制刹车）、**自反思质检**（幻觉检出重做）。（可引`case-study-bondseek-hallucination.md`） |
| "你说的循环，上下文不会爆吗？" | 第 4 层上下文治理：双轨存储（展示历史永不压缩 / 工作上下文渐进压缩）+ 子 Agent 只回摘要防窗口膨胀。（可引`case-study-bondseek-memory.md`） |
| "Agent 成本是不是很高？" | 诚实承认 + 对策：有轮数上限、检测有阈值、辅助环节用便宜模型、动态提示词静态部分缓存命中省 token |

## 🎁 核心记忆卡（面试前 30 分钟默背这三句）

> **第一句（本质）**：Agent = 把 LLM 放进 while 循环，让模型自己决定下一步干什么。
> **第二句（分界）**：Agent vs Workflow 的分界线——决策权在模型手里才是 Agent，写死的是工作流。
> **第三句（骨架）**：Agent 的骨架是循环，血肉是四个外设（记忆补状态 / 工具补手脚 / 反思补纠错 / 检索补知识），灵魂是"决策权在模型手里"。
